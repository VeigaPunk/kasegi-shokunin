`corpus/instruments/claim-package-check.py <package-dir>` is the executable gate for the claim-ready package contract that stayed documentation-only after the `ops/claim-check.mjs` checker was lost. It prints one `RULE <id> verdict=pass|fail detail=<short>` line per rule in the order below, then `package=<path> rules=8 pass=<k> fail=<m> verdict=WELL-FORMED|DEFECT exit=0|1`; exit 0 only at 8/8, 2 when the argument is not a directory. Every path it opens is built from the package root it was given: artifact paths must be relative, carry no `..`, hold no symlink at any component and resolve beneath that root, so a package cannot be graded against another package's bytes. It makes no network call and runs no git command. A read error, parse error or internal fault is a FAIL of the rule that needed the input, never a pass. The rules below are the lane contract's words at the cited lines; S067 is this entry's only external source, and it grounds the worked exemplar, not the rules.

## What the gate decides

- **R-FILES** — the six contract files are present as regular, non-symlink, non-empty files and the four JSON files decode as objects. Contract: "A claim-ready package lives at `claims/<program>/<slug>/` and contains:" (`corpus/knowledge/claim-package-contract.md:7`), the table at `corpus/knowledge/claim-package-contract.md:11-16` naming `report.md`, `claim_checklist.md`, `evidence/manifest.json`, `custodian-receipts.json`, `provenance.json`, `status.json`.
- **R-MANIFEST** — `schema_version` is exactly `evidence-manifest/v1`, `sequence` is numeric, `expected_head_sha256` is 64 hex, each artifact path is relative and confined, each declared `sha256` equals the digest the gate recomputes from the artifact bytes, each `polarity` is `positive` or `negative`, and at least one is `positive`. Contract: "`schema_version: "evidence-manifest/v1"`. Per-artifact sha256 + `polarity` ∈ {positive, negative}; ≥1 positive required." (`corpus/knowledge/claim-package-contract.md:13`)
- **R-REDACT** — `redactions[]` is non-empty, exactly one receipt binds each artifact, its `artifact_sha256` and `scanned_artifact_sha256` both equal the manifest digest, and producer and verifier are non-empty and differ. Contract: "`redactions[]`: one same-digest receipt per artifact with nonempty, distinct producer/verifier identities." (`corpus/knowledge/claim-package-contract.md:13`)
- **R-CUSTODIAN** — the chain is non-empty; every action carries a non-empty `action`, 64-hex `input_sha256` and `decision_sha256`, a non-empty `matched_grant_id` and `scope_signal` exactly `NO_SCOPE_OBJECTION`; `head_sha256` equals the last decision digest and `manifest.expected_head_sha256`. Contract: "Every action: nonempty `matched_grant_id` AND `scope_signal` exactly `"NO_SCOPE_OBJECTION"`." (`corpus/knowledge/claim-package-contract.md:14`)
- **R-PROVENANCE** — each agent carries a transition with requested and resolved models; each command carries an integer exit code; `pin.remote` is non-empty and `pin.commit` is 7-64 hex; `policy_sha256` is 64 hex; `external_effects_performed` is exactly `[]`; an attestation is present. Contract: "Agents + requested/resolved models per transition, commands + exit codes, pin (remote + commit), `policy_sha256`, `external_effects_performed: []`, secrets attestation." (`corpus/knowledge/claim-package-contract.md:15`)
- **R-STATUS** — `manifest_sha256` equals the digest recomputed over the manifest bytes; `claim_review` carries all four hard gates and both subchecks; the reviewer has an identity, requested and resolved models and a boolean fallback, and that identity differs from every producer and verifier named in the redaction receipts; `claimable: true` needs every gate `PASS` and `finding_count >= 1`, `claimable: false` needs a named blocker. Contract: "`manifest_sha256` binds status to manifest bytes. `claim_review` holds `hard_gates` + `subchecks` + `reviewer` (distinct identity, requested/resolved model, fallback flag)." (`corpus/knowledge/claim-package-contract.md:16`)
- **R-REPORT** — `report.md` matches `/scope\s+excerpt/i`, contains the exact literal `No submission performed`, contains an `https://` URL, and every whole 64-hex token it cites equals a manifest artifact digest. Contract: "literal marker "No submission performed"." (`corpus/knowledge/claim-package-contract.md:11`); "`"Scope excerpt" = verbatim policy text + URL + observed_at + content sha256`" (`corpus/knowledge/claim-package-contract.md:11`).
- **R-NOSECRET** — the walk refuses a symlink entry and any file over 5 MiB, and fails on a credential-shaped token: a private-key header, a bearer or authorization value, a labelled `api_key`/`secret`/`token`/`password`, a session-cookie assignment, or a credential-vault reference URI. It reports the shape and the first file, never the matched value. The contract states this only as "repro steps without secrets" (`corpus/knowledge/claim-package-contract.md:11`); the scan itself is the lost checker's derivation: "Regex over every non-symlink file ≤5 MiB in the package, read as UTF-8 — no text/binary filter" (`corpus/knowledge/claim-gates.md:45-47`).

Four shapes the contract leaves unstated are lane choices the gate fixes: the `artifacts` array key, the receipt field that names its artifact, the attestation object's `no_secrets` flag, and requiring an `https://` program URL. They are conventions of this lane, not contract words.

## What the gate does not decide

- **Parity with the lost `ops/claim-check.mjs`.** The contract's round-13 boundary note (`corpus/knowledge/claim-package-contract.md:18-26`) records that the lost checker never read `schema_version`, the provenance `pin`/`policy_sha256`/`external_effects_performed`, `status.severity` or `status.reward`; the gate enforces four of those as new rules, so a green run is not the lost gate re-implemented. In the other direction the lost checker's status sweep (`state: DONE`, `claimable: true`, `finding_count`, duplicate scans) is not implemented, and its global duplicate scan cannot be: the gate reads only beneath the package it is given.
- **The operator gates: submission, prior-submission, reviewer distinctness.** No submission is performed and `No submission performed` is a marker, not a receipt. Prior-submission is not checked beyond the presence of the in-package `no_duplicate_or_prior_submission` key — no registry or cross-package comparison runs. Reviewer distinctness is a case-insensitive string comparison inside one package: it cannot show that the reviewer is another party, that a review happened, or that the review was independent.
- **Whether the evidence is true.** R-MANIFEST recomputes digests from the bytes the package contains, binding the package to itself and not to any source; capture binding and source rechecks are different instruments.

## One falsifiable rule a reader can check

A package whose `report.md` omits the exact literal `No submission performed` is `DEFECT` whatever its JSON says. Check it on the committed fixture: `python3 corpus/instruments/claim-package-check.py corpus/instruments/fixtures/claim-package/defect-8-marker` prints `RULE R-REPORT verdict=fail` and `verdict=DEFECT exit=1`; appending that one literal and re-running flips the summary to `rules=8 pass=8` (measured pass 7 → 8, no other rule touched). The lost checker's prose regex `/no submission (performed|made)/i` (`corpus/knowledge/claim-gates.md:15`) would have accepted `No submission made`, so the gate is stricter than the derivation it replaces.

## One rejected over-generalization

Rejected: that a `WELL-FORMED` verdict means the package is claim-ready or safe to submit. Reason: the gate's own exemplar is deliberately `claimable: false` with three named `OPERATOR-GATED` gates, and the lost checker's `claimable === true` requirement would reject that exemplar outright; reading eight shape rules as a readiness verdict converts a contract check into a finding claim. The contract's boundary note says of those fields: "Those fields are contract-by-convention (reviewer/runbook-checked), not machine gates." (`corpus/knowledge/claim-package-contract.md:22-23`)

It is built from the advisory captured as S067 — the curl project's own CVE-2025-9086 advisory, "Project curl Security Advisory, September 10 2025" (`corpus/source-snapshots/round-43/S067.txt:69`) — and its scope excerpt quotes that document's own `Severity: Low` (`corpus/source-snapshots/round-43/S067.txt:83`) and `Affected versions: curl 8.13.0 to and including 8.15.0` (`corpus/source-snapshots/round-43/S067.txt:88`), stated as the project's position rather than as a general rule.
