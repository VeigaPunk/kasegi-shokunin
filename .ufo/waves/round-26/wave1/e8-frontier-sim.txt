How the instrument counts (summary):
- read_frontier(root) scans <root>/corpus/README.md line by line with
  FRONTIER_ROW = ^\|\s*(F\d+)\s*\|\s*([^|]+?)\s*\|\s*([^|]+?)\s*\|\s*`?([^|`]+?)`?\s*\|
  capturing (id, topic, status, entry-cell) in README order.
- main() keeps only rows whose status cell == "admitted".
- For each admitted row, the entry cell (4th column) is split on ","; each part is
  one entry path resolved relative to <root>/corpus/ (e.g. knowledge/foo.md).
- Each entry is evaluated (entry_contract + evaluate): the recheck line must name
  source-recheck.py with --manifest and --source ids that (A) cover the entry's own
  header source: ids, (B) are all listed by a schema-valid manifest, (C) are cited
  by the entry body; then the line is executed from the lane root and its exit code
  is the entry's result. PASS = no problems and exit 0.
- Summary line prints entries=<total records across admitted rows> pass=<N>
  exit=<0 if N==records and records nonempty, else 1>; exit 2 on harness/read error.
- So the per-row contribution is 1 record per comma-separated entry path in an
  admitted row's entry cell (F09 and F10 currently each contribute 2 records).
