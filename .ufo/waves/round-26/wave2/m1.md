## Hardening suggestions for wave3 / report

1. **Value-check instead of presence-count.** Replace/couple `grep -cE 'selftest cases='` with a check that `cases=<n>` equals the actual selftest case count (15 at digest 3fc0d751…), `failures=0`, and `exit=0` — e.g. `grep -E '^selftest cases=15 failures=0 exit=0$'` (exact-line match) or a small key=value parse, so M2/M3-style value drift is caught.
2. **Bind the digest in the same check.** Have the gate/harness recompute `sha256sum corpus/instruments/recheck-audit.py` and require exact equality with the `instrument_sha256=` line (and re-assert `base_sha256_control` = round-25 pinned c3c19adc…) as part of the counter command, so a receipt at a bogus digest fails.
3. **Cross-validate the receipt line against the live artifact** (e1-selftest-live.txt's `selftest_exit=0`, and c1-live.json `pass_strict=39`) using the same grep family, so a regenerated receipt cannot drift from the artifacts it claims to summarize.
4. **Exit-nonzero on mismatch.** Make the counter a compound command (`grep` + value compare) that exits 1 when any field mismatches, so the gate's exit code (not just a printed count) carries the verdict.
5. Optionally sign/checksum the whole index so any single-line alteration (including digest lines) changes the gate's expected value.
