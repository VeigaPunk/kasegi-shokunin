# ScribeRound — host tool-identity conflict between two round-67 seats (measured)

Date: 2026-11-04. Lane: /home/vgpnk/Projects/shokunin/kasegi-shokunin (base 8e2a8fe8eb92d7c824902a4b70aab027a9aacee0).

## The conflict
Two wave seats state the host's toolchain differently, and the difference is material to how a
reader should treat the thresholds in the receipt.

- `w1/RevengerMultiHead/table.txt` (host block) states:
  `tools = cut/wc/sort/head/tail/sha256sum/tr/ls/cat 0.8.0 (uutils); grep = 'grep (pi-uu-grep) 0.2.0'`
- `w1/ReviewMultiHead.md` (method note) states:
  `all binaries used were resolved under /usr/bin and hashed in final/binary-identities.json
  (GNU coreutils 9.12, grep 3.12-modified)`

## What this seat measured — the host is GNU, not uutils
Resolution is by the same mechanism the gate and every receipt use (python `shutil.which`, i.e.
PATH lookup of the bare argv[0]):

    $ python3 -B -c "import shutil,subprocess; ..."
    cut        which=/usr/bin/cut       version=cut (GNU coreutils) 9.12
    wc         which=/usr/bin/wc        version=wc (GNU coreutils) 9.12
    grep       which=/usr/bin/grep      version=grep (GNU grep) 3.12-modified
    sort       which=/usr/bin/sort      version=sort (GNU coreutils) 9.12
    head       which=/usr/bin/head      version=head (GNU coreutils) 9.12
    tail       which=/usr/bin/tail      version=tail (GNU coreutils) 9.12
    sha256sum  which=/usr/bin/sha256sum version=sha256sum (GNU coreutils) 9.12
    tr         which=/usr/bin/tr        version=tr (GNU coreutils) 9.12
    ls         which=/usr/bin/ls        version=ls (GNU coreutils) 9.12
    cat        which=/usr/bin/cat       version=cat (GNU coreutils) 9.12

Package ownership confirms it:
    $ pacman -Qo /usr/bin/cut /usr/bin/grep
    /usr/bin/cut is owned by coreutils 9.12-2
    /usr/bin/grep is owned by grep 3.12-2

There is no uutils or pi-uu-grep on PATH: scanning every PATH directory for `cut` finds only
/usr/bin/cut. A clean-environment shell (`env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/bin:/bin`)
reports the same GNU versions for all ten tools.

## Where the revenger's uutils label came from
It is a HARDCODED literal in the seat's own table emitter, not a measurement:
`.ufo/waves/round-67/w1/RevengerMultiHead/emit_table.py` lines 27-28:
    w("tools             = cut/wc/sort/head/tail/sha256sum/tr/ls/cat 0.8.0 (uutils);"
      " grep = 'grep (pi-uu-grep) 0.2.0'")
No probe in that seat's directory measures the tool versions (`probe.py` records only
`"host": {"python": sys.version.split()[0]}`); the string is written verbatim into `table.txt`.

## The MEASUREMENTS are unaffected — they reproduce exactly under GNU coreutils
This seat re-ran the revenger's key thresholds with the real PATH-resolved GNU binaries
(python subprocess argv lists, no shell; 10-20 repeats per size):

    cut  -f1 -d: f.txt missing.txt | head -n 1     (f.txt = k KiB, 1023-byte lines)
      512 KiB -> {-13}        513 KiB -> {-13:14, 1:6}   514 KiB -> {-13:17, 1:3}
      520 KiB -> {-13:12, 1:8}   524 KiB -> {-13:20}   576 KiB -> {-13:20}
    cat  f.txt missing.txt | head -n 1
      512 KiB -> {1:20}        513 KiB -> {1:6, -13:14}  514 KiB -> {-13:17, 1:3}
      520 KiB -> {-13:12, 1:8} 524 KiB -> {-13:20}        576 KiB -> {-13:20}
    grep x x.txt missing.txt | head -n 1        -> rc0 {-13} x10, stderr never names missing.txt
    grep alpha x.txt missing.txt | head -n 1    -> rc0 {2}   x10, stderr names missing.txt

These match the revenger's reported thresholds **exactly**:
  cat:  "first size with any -13 = 513 KiB (525312 B): 35/40; first size with -13 in every
         repeat = 524 KiB (536576 B): 40/40; 512 KiB = 0/40, rc 1"
  cut:  "64 KiB = 0/40, rc 1" and "65/66/67/68 KiB = 4/40, 6/40, 7/40 reach the operand"
  grep: "grep-few+missing = 2, 0/40 SIGPIPE" and "grep-many+missing = -13"

**Conclusion: the revenger's NUMBERS are correct for this host; only its tool-LABEL is wrong.**
The measurement therefore stands, and the revenger's own conclusion — that the SIGPIPE threshold
is head-specific and racy, with no portable size threshold — is unaffected.

   reviewer's tool identity is the correct one and is independently confirmed here.
2. The revenger's table is a **receipt**; per the lane's own append-only discipline it is left
   byte-identical and the correction is recorded here (as the round-66 lesson did for its r65
   routed corrections). This receipt is the correction.
3. If the L1 records any size threshold at all, it must be recorded as **measured on GNU coreutils
   9.12 / GNU grep 3.12-modified on this host**, with the repeats, and with the caveat that the
