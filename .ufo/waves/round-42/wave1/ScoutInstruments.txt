F-BIND finding (r41 wave-2 MutBindingExistence.md): two surviving mutants, and
the live-tree cause is confirmed by reproduction on a fixture lane:

  (a) MISSING-PATH — confirmed live this round (scout fixture, M2): a record
      whose `path` names NO file (file deleted, path string unchanged) prints
      `records=1 bound=1 unbound=0` exit 0. The reverse direction is absent:
      bound_paths (L434-436) is a set used only to exclude already-named files
      from the orphan check; no line ever tests that record["path"] exists.
      The instrument's own docstring disclaims it: L125-128 "The reverse
      direction (a record naming a file that is absent) is not a rule here".
      NOTE the r41 receipt's headline variant (path=S063-missing.txt WITH the
      real S063.txt still in place) is not silent — it dies as orphan-capture
      (my M1: FAIL rule=orphan-capture, exit 1). The silent variant is the
      file-deleted/no-stray-file shape, which the receipt itself flags as the
      untested-but-implied blind spot. The J6 replay artifact must therefore
      be a manifest whose record path is absent AND whose directory holds no
      extra stray capture.

      REPAIR SITE: inside check()'s `for record in records:` loop (L394-428)
      or immediately after bound_paths is built (L434-436) — both have the
      manifest dir `path` variable in scope. Add a per-record existence limb:
      `os.path.isfile(os.path.join(path, record["path"]))` for every record
      carrying a non-empty string path -> `FAIL rule=record-path-missing`
      (name of the FAIL rule is the suite's choice; the limb must also feed
      `bound`/`unbound` or the FAIL line alone suffices since exit is driven by
      `failures` at L461). Also decide non-string/absent path records: today
      `record.get("path")` non-string is silently excluded from bound_paths
      (L435-436) — a record with no `path` at all passes as bound; the repair
      should treat a missing/invalid path field as record-path-missing too.
      Path-safety note: a record path containing `../` or an absolute path is
      also unvalidated here (source-recheck's containment is a different
      instrument); an isfile() check on the joined path is the minimal repair.

  (b) URL-VARIANT — partially confirmed live: record["url"] mutation does NOT
      survive (my fixture M3 case-variant `.../RFC/rfc9116.txt` and M4 trailing
      slash both -> FAIL rule=url-mismatch record=S063 row=S063, unbound=1,
      exit 1). The surviving variant is the SECONDARY url field: mutating
      `capture_url` alone (url intact) prints bound=1 unbound=0 exit 0 (my M5).
      bind_record reads ONLY record.get("url") (L297); `capture_url`,
      `http.final_url` and `files[]` are never read anywhere in the instrument.
      The r41 receipt claims the both-fields mutation survived, which cannot
      reproduce against the current bytes — the receipt's own explanation
      (`bind_record` exact-matches record.url only) proves the checked field is
      `url`; treat the committed replay artifact as needing verification, but
      the REPAIR for the URL-variant family is to bind every URL-typed record
      field the record schema carries.

      REPAIR SITE: bind_record() L297-304 — after the `url not in tokens`
      check, cross-check `record["capture_url"]` (and `record["http"]["final_url"]`
      when present) equals the bound token / equals record["url"]; a divergent
      secondary URL field -> FAIL (e.g. rule=capture-url-mismatch). Alternative
      placement: per-record inside check()'s record loop (L394-428) beside the
      provenance limb; but bind_record already owns the row-token context, so
      L297-304 is the tightest site.

  Additional unbound surface found during this inventory (routed but outside
