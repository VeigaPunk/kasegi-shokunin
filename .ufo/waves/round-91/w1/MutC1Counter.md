# MutC1Counter — round-91 C1 counter mutation test

**Scope.** Mutation-test the frozen C1 counter
`.ufo/waves/round-91/c1/knowledge-meter.py` at the C1 landing commit, focused on the new limbs
M9 (edit equals the label-named edit) and M10 (completeness), plus M3 (line diff) and M4
(binding), with one M5 probe. Findings are routed defects and qualifiers; nothing here
re-scores C1. The frozen predicate itself passes at the landing commits (verified below).

## Method

1. `git clone -q --shared` of the lane into scratch; toplevel asserted; all later git calls name
   `-C <clone>`. The eight control variants of `controls/c1-controls-r91.sh` were rebuilt in that
   clone (candidate, no-work, partial-5-of-6, partial-own-map, superset-unlabelled-edit,
   wrong-range-454, label-ignored-457, working-tree-only).
2. Fixture identity: the candidate variant's `corpus/knowledge` tree and `resolve.py` blob are
   identical to the C1 landing commit `8a1a00c` (`4c4234cb…` / `4d578e55…`), and the base
   knowledge tree equals the freeze's (`db639230…`).
3. Baseline: the frozen counter over the eight variants reproduces the frozen transcript
   **byte-for-byte** — 8/8 blocks, 9 lines each (`baseline-vs-frozen.txt`). Verdict vector
   `0,1,1,1,1,1,1,1`. The frozen command on the real lane also returns `pass rc=0`,
   `890/1883 -> 891/1880`.
4. 36 mutants generated by single textual replacements of the frozen copy (each `old` asserted to
   occur exactly once; each mutant compiled). Every mutant was run under the **frozen C1 command**
   over all eight variants (288 runs). A mutant is *killed* when any variant's exit code differs
   from baseline, *detail-only* when only a `LIMB` line differs, *survived* when output is
   identical.
5. Survivors got either an equivalence proof or a routed control; ten routed controls were built
   and run in the same clone (each: frozen counter `rc=1`, target mutant `rc=0`).

## Routed defects (qualifiers on the frozen control set, not a re-score)

1. **F1 — `partial-own-map` confounds M10 with M6.** The variant runs the partial map while passing
   the frozen map's sha256, so M6 fails and M10's `unapplied` arm is never the deciding limb. A
   partial map with its own sha256 (R1) is the isolating control; M10-02 changes the reported limb
   line under the frozen control but not the exit code.
2. **F2 — `wrong-range-454` confounds M9 with M6.** Same shape: the wrong-range map is run with the
   frozen map's sha, so M6 fails and M9's edit-equality arm is masked. R2 isolates it.
3. **F3 — `superset-unlabelled-edit` confounds M3 with M1.** The extra edit changes the rate to
   `891/1881`, so M1 fails and M3's "unmapped edit" arm is never decisive. R6 (rate-neutral edit)
   isolates it; M3-06 shows the limb line changing while the exit code does not.
4. **F4 — uncovered M3/M4/M5 arms.** No frozen control exercises duplicate map rows, a line-count
   change, a scope file-set change, a map row whose `old` is absent from its base line, an
   out-of-range anchor, a cross-file label, or a duplicate basename outside `.ufo/`. Each has a
   re-runnable control (R3, R4, R5, R10, R7, R8b, R9) and each control kills its mutant.
5. **F5 — redundant guards (not defects).** `M10`'s `unlabelled` arm is unreachable whenever M9
   holds (M9 binds every mapped site to a label); M4's INTERNAL check is implied by the basename
   check (a tracked `corpus/knowledge/<name>` classifies INTERNAL); `bool(rows)` in M4/M10 is
   implied by M3/M9; FIXNAME/FIXDASH order is immaterial (disjoint); the `^` anchors are
   redundant under `re.match`. These survive mutation by construction, and the proofs are in
   `survivor-proofs.txt`.
6. **F6 — M3's `missing` arm is subsumed by `bad` for `count(old) >= 1`.** It is observable only
   when a map row's `old` is absent from its base line while the after line is unchanged; R10
   builds exactly that case (`old_not_once=1`, orig `rc=1`; mutant `rc=0`).
