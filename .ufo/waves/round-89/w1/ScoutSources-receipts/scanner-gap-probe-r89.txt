# IMPORTANT — the scanner reports only the FIRST non-allowed match per shape per file

# first hit of that shape). So in a multi-line fixture, a later line of the SAME shape is not

# verdict is not a dedup artifact. All probes used --allow /dev/null.

# --- Probe A: CloudFront signed COOKIE (lead L2) is NOT covered by the landed scanner. ---
# Isolated single-line fixtures (values elided; the printed line is the scanner's own summary):
#   "Set-Cookie: CloudFront-Signature=<40+ base64url chars>"          -> hits=0 rc=0
#   "Set-Cookie: CloudFront-Key-Pair-Id=<8..32 uppercase alnum>"      -> hits=0 rc=0
#   "Set-Cookie: CloudFront-Signature=<40+>&CloudFront-Key-Pair-Id=<8..32>" (same line, "&")
#                                                                         -> hits=0 rc=0
# Two independent causes, each isolated:
#   (i)  LEFT BOUNDARY. The landed rule's boundary is
#          (?:(?<![A-Za-z0-9_-])|(?<=\\u0026)|(?<=%26))
#        The character before "Signature" in "CloudFront-Signature" is a hyphen, which is inside
#        [A-Za-z0-9_-], so the negative lookbehind fails and the cookie name is skipped.
#        Isolated confirmation: "X-Signature=<40+>&Key-Pair-Id=<8..32>"  -> hits=0 rc=0
#                              "a-Signature=<40+>&Key-Pair-Id=<8..32>"  -> hits=0 rc=0
#                              "Signature=<40+>&Key-Pair-Id=<8..32>"    -> hits=1 rc=1
#        i.e. the rule fires only on a bare "Signature=", never on a hyphen-prefixed one.
#   (ii) SEPARATOR. The rule requires the two parameters to be joined by "&", "&amp;" or "\u0026".
#        Isolated confirmation: "Signature=<40+>&Key-Pair-Id=<8..32>"    -> hits=1 rc=1
#                              "Signature=<40+>;Key-Pair-Id=<8..32>"    -> hits=0 rc=0
#        In a Set-Cookie header the pair is separated by "; Domain=..." (or by a newline), so the
#        adjacency requirement fails as well.
# Re-runnable probe (values are shapes, not secrets):
#   printf 'Set-Cookie: CloudFront-Signature=%s\nSet-Cookie: CloudFront-Key-Pair-Id=%s\n' \
#     "$(printf 'A%.0s' {1..48})" "$(printf 'K%.0s' {1..14})" > $S/p.txt
#   python3 -B corpus/instruments/capture-secret-scan.py --files $S/p.txt --allow /dev/null
#   # observed: CAPTURE-SECRET-SCAN mode=files scanned=1 hits=0 ... rc=0
# Consequence: a captured CloudFront signed-cookie Set-Cookie header would pass the scanner
# unflagged. This is a coverage gap, not a defect in the round-89 frozen claim, which covers
# the signed-URL shape only.
# Length note for the round-90 designer: AWS's own documentation example cookie signature value
# is 28 characters long, below the landed rule's {40,} minimum, so a cookie rule needs its own
# length floor (the URL example at S128/S130 is far longer because it is a padded example).
