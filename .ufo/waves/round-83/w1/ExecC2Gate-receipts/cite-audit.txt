    124| Is the API rate limited?
    125| No. Currently there is not a limit on the API.
    126| Are there any response size limits?
    127| The API has a response size limit of 32MiB when using HTTP/1.1. There is no limit when using HTTP/2.
    128| We recommend using HTTP/2 for queries that may result in large responses (e.g. big OSV Linux queries).
    129| What are OSV.dev’s service level objectives (SLOs)?
    130| OSV.dev strives to provide reliable vulnerability information to our users. To support that goal, the following service level objectives are targeted:
    131| Availability, website and API: 99.9% measured on a 7 day rolling window.
    132| Latency: Website: P50 ≤ 300ms, P90 ≤ 500ms, P95 ≤ 1s, that is 50% of requests will be faster than 300ms, 90% of requests will be faster than 500ms, and 95% of requests will be faster than 1s.
    133| API, per endpoint: GET /v1/vulns/{id}: P50 ≤ 100ms, P90 ≤ 200ms, P95 ≤ 500ms
    134| POST /v1/query: P50 ≤ 300ms, P90 ≤ 500ms, P95 ≤ 1s
    135| POST /v1/querybatch: P50 ≤ 500ms, P90 ≤ 4s, P95 ≤ 6s
    136| Data Freshness: Data sources no more than 15 minutes stale, 99.5% of the time.
