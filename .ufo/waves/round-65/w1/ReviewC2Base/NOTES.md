## 1. How `before.txt` was produced

`before.txt` is generated by `/fast/scratch/hyaku/kasegi-r65/ReviewC2Base/gen_before.sh`
(scratch, not committed), which for every measurement prints

```
$ <the exact command>
<its literal stdout+stderr>
[exit=N]
```

and only then emits the `BEFORE <name> <value>` lines. Each `BEFORE` value was then
re-read against the printed output in the same file (grep of the summary lines), not
transcribed from memory. The generator path is recorded so the file can be regenerated
byte-for-byte from the same base.

Two working roots are used and the file labels which is which:

* **lane root** `/home/vgpnk/Projects/shokunin/kasegi-shokunin` — canonical, because
  every published `recheck:` line begins `cd /home/vgpnk/Projects/shokunin/kasegi-shokunin &&`;
* **export** `/fast/scratch/hyaku/kasegi-r65/ReviewC2Base/base` — `git archive <base> | tar -x`
  into scratch, used for the cross-checks and for anything that could touch the tree.

## 4. S098 source screen — what was measured vs what is judgement

Measured (commands and literal output in `source-check.md`): two instrument captures
byte-identical at 229255 raw / 170137 snapshot / 1573 lines / sha256 `cfa42e23…`;
raw sha256 also identical (`3a1b5c1a…`) with `Last-Modified: Mon, 26 Jan 2026
14:43:46 GMT` and no ETag; offline re-parse of the saved raw bytes reproduces the same
digest; the trailing-slash URL resolves to a different page path (`v1-1`) with different
raw bytes and an identical text snapshot.

Judgement (flagged as such, not measured):

* that the document is a good F44 *coverage* object. The evidence I can give is
  structural: 6 service areas, 84 `Function` headings, 81 `Sub-function` headings, an
  explicit PSIRT-vs-CSIRT section (L243) and organisational models (L249/L259), against
  F43's phase×five-role matrix (S095) and F06's multi-party coordination guidelines
  (S018). That is a subject difference, not a publisher difference — the entry must
  state it that way.
* that the ISO citations inside the document are a hazard rather than a defect: the
  framework cites `ISO/IEC 30111:2013` and `ISO/IEC 29147:2014` while the lane's F38
  rows S089/S090 record the 2018/2019 editions. If the entry repeats the framework's
  editions as current, it collides with F38. The entry must attribute them to the
  framework.
* that reusing id `S098` is acceptable. The registry ends at `S097` and nothing current
  mentions `S098`, but three round-24/28 wave receipts (kept in-tree) used `S098` for a
  different, never-landed staged row (`www.055110.com`). No current document carries it
  (`grep -n 'S098' LOG.md SKILL.md SCORECARD.md PROVINCE.md corpus/README.md` → empty;
  `grep -rn '055110' … corpus/` → empty). The receipt should say "id reused from an
