1. EXPORT-MODE GATE STRUCTURE
===============================================================================

P1.1 ADOPT — tar-member containment is a separate, testable step.
kaidoku-shokunin/tools/round-44/c2-counter.py:752-786 `extract_tar` never calls system
`tar`: members have `./` stripped, absolute names dropped, `target` must satisfy
`target.startswith(dest + os.sep)`, and a symlink is only created after `os.path.abspath`
of the link target is proven to stay inside `dest`. c2-counter.py:790-802 `export_tree`
feeds it `git archive --format=tar` and raises `Unevaluable` on a non-zero archive, so a
ref that exports partially is exit 2, never a short tree.
Informs: r43-closure.sh export build (the r42 driver's `git -C "$LANE" archive | tar -x`,
r42-closure.sh:86-92). `tar -x` alone honours `..` and absolute members; the export feeds
every K-check, so one escaping member would let a K read a path it must not see.
Note the frozen contract does not require the hardened extractor; this is the cheap
insurance version, and it is the only sibling form that makes containment an explicit line.

P1.2 ADOPT — export the tree into a temporary directory that dies with the process, and let
SIGTERM reach the cleanup.
kaidoku-shokunin/tools/round-44/c2-counter.py:13-16 (tree exported into `--work`, read-only);
kama-shokunin/tools/round42-digest-audit.py:290-294 (`tempfile.TemporaryDirectory` around the
`tar -x`); kama-shokunin/tools/round41-pinwatch-audit.py:210-215:
    export = tempfile.mkdtemp(prefix="r41c2-")
    atexit.register(shutil.rmtree, export, True)  # round 42: remove the export (R41A10-10)
    signal.signal(signal.SIGTERM, lambda *_: sys.exit(143))  # round 42: SIGTERM must reach atexit
Informs: r43-closure.sh driver. The r42 driver creates `$WORK/export` with `rm -rf` at
r42-closure.sh:86 and never removes it on exit, and installs no signal handler (grep shows
no `SIGTERM|atexit|trap` in r42-closure.sh). A cancelled seat therefore leaves the export
behind — the same class R41A10-10 fixed in kama. SIGTERM→exit 143 is the part most lanes
forget: without it `atexit` never runs on a killed run.

P1.3 ADOPT — "exit 2 means could-not-evaluate and never counts as a pass" phrased in the tool.
kaidoku-shokunin/tools/round-44/c2-counter.py:23-24: "Exit 2 means COULD-NOT-EVALUATE, never
'not a pass': it never counts toward the target." chousa-shokunin/tools/research-gate.sh:5968-5970

masquerade as clean"). Informs: r43-closure.sh header and the K9/K10 self-acceptance arms —
the C1 claim needs the *third* value to be visibly distinct from red, and the distinct
`ref-not-found` red keeps the same job for an unresolvable ref.

P1.4 HOLD — kasegi's export-mode gate is already the strictest form read.
kasegi corpus/instruments/r42-closure.sh:1-27 declares usage, the transcript grammar, and the
exit table in the header; :56-60 refuses a plain run with exit 2; :66-71 prints
`ERROR ref-not-found ref=<hash> closed=0 exit=1` for an unresolvable ref. No sibling
instrument read combines "plain run refused" + "unresolvable ref is a *red*, not a usage
error" in one file. r43-closure.sh must reproduce these three shapes byte-for-byte; the
sibling files are useful only as the place to check that the doctrine text is not narrowed.

5. WHOLE-TOKEN MATCHERS
===============================================================================

P5.1 ADOPT — the hyphen/apostrophe joiner rule.
chousa-shokunin/tools/research-gate.sh:1867-1906. `TOK_WS` and `TOK_PUNCT` are the two
boundary classes; membership is asked with `[[ $SET == *"$c"* ]]` so a multibyte character
misses both and is therefore a word character (:1860-1866). `tok_left_ok`/`tok_right_ok` then
special-case `-` and `'`: they are boundaries *only* when they do not join two word
characters — "word-internal joiner" (:1885-1891, :1899-1905).
Informs: r43-closure.sh `token_at` (r42-closure.sh:348-370). Kasegi's `TOKEN_BAD` is
`0123456789/.=_` + ASCII alnum, so `-` and `:` are treated as boundaries. Measured over the
r42 `token_at` source, re-executed: `closed=19/19-rc1` and `closed=19/19:61` both read as
whole tokens (2 of 6 boundary probes diverge from the intended reading; the four digit,
comma, paren and control probes agree). The same two probes under chousa's `tok_right_ok`:
the hyphen case becomes a non-boundary (correct), the colon case still passes — `:` is in
`TOK_PUNCT` there too. So the joiner rule fixes the hyphen class outright and neither lane
closes the colon class; if K15 quotes `closed=` values, take the joiner rule and declare the
colon as a named limit rather than implying it is closed.
Command: both readers re-executed verbatim in python3 from their source bytes —
`TOKEN_BAD`/`token_at`/`value_present` from r42-closure.sh:348-370, and
`TOK_WS`/`TOK_PUNCT`/`tok_word_char`/`tok_right_ok` from research-gate.sh:1867-1906 — over the
probes `closed=19/19 exit=0`, `-rc1`, `:61`, `,`, `)` and `190`. Six probes: four agree everywhere,
kasegi diverges on two (hyphen, colon), chousa on one (colon).

P5.2 ADOPT — hex-class boundaries, not `\b`, for digests.
kama-shokunin/tools/digest-ledger.py:70: `TOKEN = re.compile(r"(?<![0-9a-fA-F])[0-9a-f]{64}(?![0-9a-fA-F])")`,
with the limits named at :39-53 ("only exact 64-character runs are tokens. A cited 'digest' of
another length (a 65-character run, ...), an upper-case digest, abbreviated digests ... are
not seen. A mixed-case neighbour ... is not a token boundary either"). tsukuroi-shokunin/tools/check-report-receipts.py:23-30
applies the same shape to git abbreviations: `HEX = r"[0-9a-fA-F]{4,40}"` with
`(?<![0-9a-fA-F])(...) (?![0-9a-fA-F])`. Informs: claim-package-check.py R-MANIFEST (per-artifact
sha256) and R-CUSTODIAN (`head_sha256` equality). A 64-hex field matched with `\b` accepts a
65-hex run's prefix; the hex class does not. Kasegi's digit-extension probe
(`closed=13/13` vs `closed=13/130`, r42-closure.sh:562-563) is the same insight for a decimal
token; digests need the hex form.

P5.3 ADOPT — state the matcher's ceiling and confirm the whole span.
chousa-shokunin/tools/research-gate.sh:1922-1923 names the ceiling
(`TOK_DIRECT_SPAN_MAX=32764`, `TOK_CHUNK_BYTES=4096`) and :1962-1990 matches the span's first
chunk, then confirms each candidate with `[[ ${hay:offset:slen} == "$span" ]]` — "a chunk
match alone is not the span, and the confirmation is what makes a mutated or split span read
as absent". Informs: r43-closure.sh K14 (the `corrections=<n>` literal) and K18 (the claims.json
"before" literal, which the C1 control shows as a long sentence). A prefix match over a long
literal turns a truncated or split quote into a pass; the chunk-plus-confirm shape is the
fix, and the named ceiling is what makes the behaviour auditable rather than accidental.

P5.4 HOLD — `\b` is adequate for word tokens and wrong for everything else.
mori-shokunin/tools/mori-routed-r24.py:174 `D5_ROUND1_RE = re.compile(r"\bround\s+1\b")` with
the comment "round 1 as a whole token: round 12 and round 13 must not match" — correct here
because both edges are letters, and it is the cheapest form. tsukuroi-shokunin/tools/check-kernel-taint.py:241-243
shows the narrower deliberate variant for row IDs: `(?<![A-Za-z0-9])%s(?![0-9])` — the right
edge blocks only digits, so an `S###` id followed by a letter still matches. That asymmetry is
intentional for `S`+digits and would be a defect if copied onto `closed=` or a digest. Use
`\b` only where both edges are guaranteed word characters.

P5.5 HOLD — kasegi already carries a boundary-probe table; extend it, do not replace it.
r42-closure.sh:561-572 `BOUNDARY_PROBES` is ten `(hay, needle, want)` rows including
`closed=13/13` vs `13/130` / `13/13x` / `xclosed=` / `13/13/5` and `failures=6` vs `60` /
`6.5`, summed at :581-583 and required complete before J2 can close. Informs: K2/K15. The
right move is to append the hyphen and colon rows above to this table, so the r43 suite
carries the measured divergence rather than a prose promise.

"the bypass". Informs: any K-check that reads SCORECARD.md / LOG.md section bodies (K14, K17,
K18). Kasegi's r42 fence handling exists (`fence_scan` at r42-closure.sh:306, `outside_lines` at
:333, `fence_open_at_eof` at :337-342); the rule to hold is that `fence_open_at_eof`
returning True must make a section-boundary check red, not lenient.

P6.4 ADOPT — a child git process gets a built environment, not the ambient one.
kotodama-shokunin/tools/harness/receipt_guard.py:56-64 strips every `GIT_*` name from the
inherited environment and sets `GIT_OPTIONAL_LOCKS=0`, `GIT_NO_REPLACE_OBJECTS=1`, `LC_ALL=C`
on `git --literal-pathspecs -C <root>`. Informs: r43-closure.sh's `git archive` and the K12
deletion-walk fixture. `GIT_NO_REPLACE_OBJECTS=1` is the load-bearing one for a gate that
compares blob identities: a replace ref in the export repo makes `git cat-file` answer a
different object than the bytes on disk, and `--literal-pathspecs` stops a declared path
containing glob characters from selecting siblings.

P6.5 ADOPT — fail-closed *ordering* across a chain of digest links.
kaidoku-shokunin/tools/round-42/fetch-carrier.py:59: "Fail-closed ordering: for each carrier
every digest link is checked *before* the next"; :2 "fail-closed at every link".
Informs: claim-package R-MANIFEST → R-REDACT → R-STATUS, which form a digest chain
(artifact sha256 → redaction same-digest receipt → `manifest_sha256`). Grading all eight rules
concurrently lets a later rule read a digest a failed earlier rule never established; the
ordering rule is what makes `pass=8` mean eight links, not eight independent checks.

===============================================================================
7. CONTRADICTIONS (the L1 decides; nothing here edits a sibling)
===============================================================================

X1. "Absence is exit 2" must NOT be imported for an unresolvable ref.
chousa-shokunin/tools/research-gate.sh:5968-5970 makes absence/malformation exit 2 so that cannot-compare
cannot masquerade as clean. kasegi's frozen C1 contract says the opposite for one specific
object: an unresolvable ref prints `ref-not-found` and exits *1*, and the kill rule makes
"an unresolvable ref does not print its distinct ref-not-found red" a defeat. Both are right
about different objects — an absent *input baseline* is cannot-compare (2); an absent *ref*
is a red (1), because the ref is what is being graded. r43-closure.sh must not fold the two.
This is the highest-risk import in the scan: it reads as a principle and is a contract
violation in this position.

X2. Exit 3 must not enter the r43 exit table.
kaidoku-shokunin/tools/round-34/replay-gate.py uses `3` for UNEVALUABLE and `2` for REFUSED
(SELFTEST_CASES at :156-163, the mutant expectations at :166-172). kasegi's frozen table is 0/1/2 only
(r42-closure.sh:26-27), and the C1 kill rule names "a plain run exits other than 2" as a
defeat. Take kaidoku's *mutant grammar* (P3.1, P3.2) and kama's *tautology arm* (P3.6);
leave its exit numbering.

X3. A summary line whose shape varies by condition is not available to kasegi.
mado-shokunin/tools/mado-geometry.py:65-70 deliberately prints `maximized=`/`fullscreen=` only when
maximized+fullscreen > 0, "so a dump with no maximized or fullscreen matched client prints the
round-43 line unchanged" — a calibrated exception for a monitor dump. kasegi's equivalents
divide cleanly: a `K<n> payload=k=v,...` line may grow fields between rounds (r42's payloads
did), but the summary lines (`closed=19/19 exit=0`, `selftest cases=19 failures=0`,
`package=… rules=8 pass=<k> fail=<m> verdict=… exit=…`) are fixed field sets, because K8/K10
and the C2 summary are themselves parsed. Do not adopt the conditional-shape licence.

X4. A committed `.expected` file may not be the only witness, and an in-code table may not be
the only witness — but kasegi cannot make the *fixture* the witness either.
kotodama-shokunin/tools/gates/handoff-packet-check.py:697-701 requires the committed file, the in-code table, and
the emitted set to agree. kasegi's C2 additionally requires nine *separate* fixture
directories that each print `verdict=DEFECT exit=1` with their own rule failing — a stronger
requirement than kotodama's single fixture. Adopt the triple-agreement assertion; do not
adopt kotodama's single-fixture economy, which would satisfy the check while leaving eight
defect classes unexercised.

X5. The r41 SIGPIPE class is closed in r42 and must stay closed.
mori-shokunin/tools/mori-census.sh:3301-3324 is the fix (capture to `$OUT_FILE`, grep the
file) for producer-pipe consumer races, and mori records the class at
corpus/lessons/2026-10-15-selftest-grep-sigpipe-race.md:4-30 ("grep -q exits the moment it
sees a match … pipefail makes the pipeline's rc 141 … the `||` guard reads rc≠0 as 'no
match'"). Kasegi's r41 suite carries 12 such sites (r41-closure.sh:904, 973, 1029, 1030, 1031,
1186, 1570, 1571, 1572, 1642, 1935, 1936; counted with `grep -c 'grep -q'` → 12);
r42-closure.sh carries 0. This is not an import but a regression corpus: if any K14-K19 arm is
written in bash, those twelve sites are the shapes not to reproduce. Kasegi has no lesson file
recording the class (no `corpus/lessons/*` mentions sigpipe), so the r42 fix currently rests
on the code alone.

===============================================================================
8. WHAT NOT TO TAKE
===============================================================================

- A per-lane `tools/` layout. Siblings put instruments under `tools/`; kasegi's contract
  names `corpus/instruments/`, and every counting command in the frozen claims is written
  against that path. Path shape is part of the claim.
- Interactive/stdin surfaces. kotodama's `-` stdin arm and mado's stdin JSON arm are useful
  for tools called by hand; r43-closure.sh is export-mode only and a stdin arm would be a
  second way in, which the plain-run refusal exists to prevent.
- Fuzzy or "review-level" verdicts. The `FAIL / REVIEW / HOLD` three-level vocabulary
  (kotodama-shokunin/tools/gates/handoff-packet-check.py:49-70) is right for a document gate with judgment; the
  K14-K19 checks are mechanical, and a review level would give a silent third state to a
  predicate that must be closed=0|1.
