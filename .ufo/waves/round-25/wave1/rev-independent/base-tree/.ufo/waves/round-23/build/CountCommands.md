# CountCommands — round 23 measurement reproducibility

## Finding: source revision is named, but the measured filesystem is not frozen

**Axis/scope:** `depth:verifiability`, C1 (`claims.json`). I did not assess C2 coverage/admission. No production files were edited and no tests/builds were run. The `lsp` device is not mounted (`read xd://lsp` returned “No such tool”), so there are no LSP caller/diagnostic results.

**Evidence.** `claims.json:3` pins base `922a4dde90b60b465e2b8b241d1fe363f1f27e98`. `before-instruments.json:2-3` likewise records that revision and says `git archive master export; actual host FS; no git/runtime metadata`; its resolver result is `mirror=0` (`before-instruments.json:5-14`). This is a useful source pin, but “actual host FS” is not a repeatable filesystem specification, and the durable record has no filesystem/environment manifest or hashes of the generated TSV/Markdown (the recorded output paths are under ephemeral `/tmp/kasegi-r23-xuj7ohl9/before/`).

The detector makes that omission observable: `resolve.py:101-110` selects `$KASEGI_MIRROR`, else the first existing candidate under `$HOME`, else the canonical absent path; `resolve.py:214-234` then classifies from filesystem existence. `README.md:86-101` documents the same environment-dependent selection and stale-byte rule. On this review host, `HOME=/home/vgpnk`, `KASEGI_MIRROR` is unset, and both candidate mirror directories are absent. In contrast, the existing real-CLI fixture `test_resolve.py:67-74, 106-133, 176-179` puts `ops/rank.mjs` in a relocated mirror and asserts that the identical citation `~/Projects/the-bounty-hunter/ops/rank.mjs:1` is `RESOLVES`. With the selected mirror absent, the current resolver’s explicit-mirror branch returns `GONE` for that missing suffix (`resolve.py:214-222`). Thus identical source bytes and citation text can yield different TSV/counts from different filesystem states; the source revision alone does not reproduce `mirror=0` or the census.

**Concrete acceptance condition.** Accept a before/after measurement only when its manifest identifies the observed master commit (`git rev-parse master` must equal `922a4dde90b60b465e2b8b241d1fe363f1f27e98`; export that exact object with `git archive 922a4dde90b60b465e2b8b241d1fe363f1f27e98`, never jj `@` or a detached-workspace snapshot), hashes the frozen source/input and output bytes, and captures a hermetic filesystem/environment fixture: `HOME`, `KASEGI_MIRROR`, candidate-root contents/absence, file bytes and symlink targets for paths the resolver can inspect. Run the same copied CLI twice against that fixture and require byte-identical stdout, TSV and Markdown. A concrete counterexample to substituting jj `@`: current `jj st` reports working-copy `@` at `c8f383da` with parent `922a4dde`/`master`, while `git rev-parse master HEAD` returns `922a4dde` and the worktree has tracked modifications plus untracked corpus markdown. `resolve.py:250-275` walks the supplied tree’s `SKILL.md` and `corpus/**/*.md`; therefore a live `@` tree is not the frozen master archive input.

**Limit:** This review establishes the filesystem dependency and the missing repeatability record; it does not rerun the baseline/after instruments, assert a production regression, or verify the wave’s final measurements.
