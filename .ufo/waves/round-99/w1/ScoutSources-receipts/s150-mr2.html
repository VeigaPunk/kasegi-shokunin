What does this MR do?

This MR adds the implementation for generating assignment-like regex programatically for a given vendor pattern. Here's the details:

Rule Schema Change

We introduce assignmentContext property in the $rule schema which contains the following properties:

  1. keywordGroup <string> : Comma(,) separated keywords to use when combining them into a variable name on the LHS of the assignment-like expression. In addition, this syntax supports two keyword alternatives:
    1. Optional(?): Append question-mark(?) at the end of the keyword if it is optional, which will create a combination of variable names with and without optional keywords.
    2. One of(|): Separate two or more keywords by one-of symbol (|) such their combinations are generated. The variable names in the regex are generated in the same order of appearance.
  2. keywordGroupType <enum: raw/ multi_case>: Indicates whether to inject keywordGroup directly as provided, or generate multiple case variant combinations for the left-hand side of the expression. This property is mutually exclusive to caseVariants, either one can be defined. This is useful when the combination of keyword alternatives(? and | ) and case variants go beyond a defined limit, in that scenario, we could use raw type to represent a value/regex fitting our usecase.
  3. caseVariants <enum: CONSTANT_CASE, snake_case, camelCase, kebab-case, Kebab-Upper-Case,PascalCase, dot.case>: Array of case variants to consider when generating the combination of variable names. The variable names in the regex as placed in same order of the case variants are defined. This is useful when we observe a particular case occurs commonly than others, which improves the performance of the regex.

With the above changes, rule.regex property can not contain only the RHS side i.e., vendor pattern in the rule schema. During the rule distribution, this property's value will be replaced by assignment regex pattern.

Sample

[[rule]]
id = "test"
regex = "[a-z]{32}\b"

[rule.assignmentContext]
keywordGroup = "api?,secret,key"
caseVariants = ["CONSTANT_CASE", "snake_case", "camelCase"]

Generated Regex:

(?:API_SECRET_KEY|api_secret_key|apiSecretKey|SECERT_KEY|secret_key|secretKey).{0,8}[:=].{0,8}([a-z]{32})\b

AzureAPIManagementDirectKey rule changes

To realize the above assignment regex feature, I have modified AzureAPIManagementDirectKey rule compatible with assignment context changes. The tests are passing.
