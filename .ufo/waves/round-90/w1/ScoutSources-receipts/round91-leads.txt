FINDING on coverage — what push protection covers that capture-secret-scan lacks:
  * The page's own rendered table is CLIENT-PAGINATED: the captured snapshot shows only the first
    alphabetical slice of providers (1Password .. Apify, 25 pattern rows) plus the marker
    "Previous123456…22Next" at line 675. The full set is 22 pages.
  * The complete set lives in the page's embedded JSON payload (531 entries, 207 providers), which the
    instrument's HTML conversion strips, so it is NOT in the snapshot. Counting hasPushProtection=true over
    that embedded payload gives 465 of 531 patterns with push protection; the flag is per-pattern, per-provider.
  * capture-secret-scan detects no provider-prefixed token on its own: bare values of the shape
    ghp_/gho_/github_pat_/npm_/xoxb-/sk-ant-api03-/sk-proj-/dd_api_/sk_live_ produce NO HIT; they are caught
    only when a key name (token=, api_key=, secret=) precedes them, via the generic `credential` shape.
    Push protection covers the bare values by prefix and partner rule. This is the concrete coverage gap.
  * The GitHub rules line 616 also bounds push protection to the most recent token versions, so a
    prefix-only rule copied from this page would be version-sensitive.

WHY THIS IS THE RIGHT THIRD LEAD for the intake gate's known limit:
  The scanner's own docstring lists "CloudFront signed cookies (CloudFront-Signature)" as a known limit,
  and this page is the first-party document that defines the cookie-borne form. Measured on the landed
  scanner: a Set-Cookie header carrying that signature is NOT detected, and the same value in a signed
  URL query is also NOT detected at 32 characters (the cloudfront shape needs 40+ characters plus a
  Key-Pair-Id parameter in the same query). So the cookie form is a real, sourceable gap, not a re-reading.
  A GCS V2 signed-URL page was also opened as a candidate for this slot (Google Cloud Storage, V2 signing
  process, legacy; sha256 517f22a3669fb2e8b803637684476dc70f3e49451a03125e75c0cef4ef87de07, 262 lines;
  it names the parameter GoogleAccessId at line 159) and was set aside: the scanner's docstring already
  lists that GCS V2 shape as a known limit, so it would restate a limit rather than open new ground,
  and the page carries no example of the query form to quote.
