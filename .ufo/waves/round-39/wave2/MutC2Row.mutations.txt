## 3. Findings against the frozen C2/E5 predicates

1. The C2 kill-rule limb "census exit != 0" guards exactly two of the six
   frozen S057 cells (NF shape, opened date). Tier, kind, status and
   source-cell content — the cells that carry the row's evidentiary meaning —
   drift without moving the census exit code.
2. E5 binding "source cell carries exactly <page URL>" is unenforced by both
   instruments: the census reads only the first URL per cell; no awk command
   reads URLs at all.
3. In-enum drift (docs→spec, mined→queued) is structurally invisible to the
   enum-violation checks by design; only a pinned expected histogram (tier,
   status) or a per-row cell pin would catch it. The lane currently pins
   neither in CORPUS.md's census block.
4. Tier downgrade of a mined, used row surfaces only as W01 — a warning class
   the census itself documents as "warnings do not affect clean lanes". Under
   the frozen kill rule this still trips via the "new W/E code" limb, but the
   tool's own contract treats the lane as clean (exit 0, `file ok` printed).
5. Defense-in-depth note: the awk malformed-row counter and the used-by
   existence check are mutually exclusive (NF!=13 vs NF==13 conditions), so a
   malformed mined row escapes the used-by check; the fleet census has the
   same shape (E01 `next` skips remaining per-row checks).
6. Do-nothing controls hold: the frozen counting command exits 0 on the real
   lane; the pristine mirror reproduces it; selftest 96/0; the two pre-existing
