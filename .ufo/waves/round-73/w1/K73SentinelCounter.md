## (1) What a repository-controlled recheck value can do in the counter's child process

Counter: `corpus/instruments/recheck-cwd-census.py` (read in full, 151 lines). `census()` (L61) takes the FIRST line starting `recheck:` in each `corpus/knowledge/*.md` (L36-41) and hands the whole value to `run_foreign()`:

- **Arbitrary shell execution** — L51: `subprocess.run(["bash", "-c", value], cwd=scratch, env=env, ...)`. The value is repo content; any shell grammar works (pipes, `$(...)`, redirects, background jobs). This is the instrument's documented function (docstring L5-8: "reads the FIRST `recheck:` line and reports … run by `bash -c` in a fresh foreign scratch cwd"), so it is the trust boundary, not a defect: commit access to `corpus/knowledge/*.md` = code execution on any machine that runs the census with `--root` at that tree.
- **Network access** — nothing restricts the child: no env scrub beyond TMPDIR, no sandbox/unshare/seccomp. A recheck value containing `curl … | bash` would run with network. No such value exists today (§2, zero hits).
- **Reads of credential paths** — cwd is the scratch, so lane-relative reads fail, but absolute paths resolve normally (`cat /home/vgpnk/.ssh/…`, `~/.env`, any file the user can read). Enabled by the same L51 with `cwd=scratch` (L46) as the only isolation.
- **File writes outside the scratch** — same mechanism; absolute-path writes land anywhere the user can write (lane tree, `~/.local/bin`, fleet-root tracked files). The counter cleans only its own `mkdtemp` scratch (L58) and cannot undo child writes elsewhere. **Executed proof:** fixture recheck `cat <abs-canary> > <abs-outside-proof> && env >> <abs-outside-proof> && (sleep 130; touch <abs-orphan>) & sleep 125` produced `outside-env-proof.txt` (14,260 bytes, line 1 = `sentinel-canary-standin`) outside the scratch, via `TMPDIR=$S/tmp python3 …recheck-cwd-census.py --root $F --lane $F --verbose` (census rc 1, wall 120 s).
- **Environment exposure** — L48: `env = dict(os.environ)`; the child inherits the counter's entire environment. **Executed proof:** the proof file's `env` dump is 275 lines (WINDOWID, HYPRLAND_CMD, npm_config, GUM_* …); the only override is L49 `env["TMPDIR"] = scratch` (dump shows `TMPDIR=…/tmp/recheck-cwd-s_r3iy9f`). Any credential present in the operator's env crosses into repo-controlled code.
- **Unbounded runtime** — bounded per entry at `TIMEOUT = 120` (L33, L53) counting as `-1` → `exit_other` (L55-56, L13). Two unbounded components: (a) serial worst case 88 entries × 120 s ≈ 2.9 h wall — **executed:** one hostile entry held the census exactly 120 s (`foreign_exit=-1`, `RECHECK-CWD … exit_other=1`, wall=120 s); (b) **backgrounded grandchildren survive the timeout kill** — `subprocess` on timeout kills only the bash PID (no `start_new_session`, no killpg), so `cmd &` is reaped never. **Executed:** the fixture's `(sleep 130; touch orphan-landed) &` fired ~10 s after the census had returned and killed bash (`orphan-landed`, mtime 04:58, census done 04:56).
- **Output memory** — L52 `capture_output=True` buffers the child's unbounded stdout+stderr in RAM before discarding it (only `returncode` is used, L54): a recheck printing indefinitely grows memory until the 120 s cap. Code-read only; not executed.
- **Cleanup races** — L58 `shutil.rmtree(scratch, ignore_errors=True)` runs while surviving orphans may still hold the scratch as cwd; failures are swallowed silently. **Executed:** with the orphan alive past cleanup, residue was still zero (`find $S/tmp -mindepth 1 | wc -l` = 0 after the probe), so no residue observed; the swallowed-failure path remains a latent risk.

**Stated guarantee "no path is hard-coded under /tmp" (docstring L16-17): HOLDS.** The only `/tmp` string in the file is that docstring sentence itself. Every temp path is `tempfile.mkdtemp(dir=env_tmp)` with `env_tmp = os.environ.get("TMPDIR") or None` (L46+L65 census, L102 selftest); with TMPDIR unset, the stdlib's own candidate fallback applies — stdlib behavior, not a counter hard-coding. `DEFAULT_LANE` (L32) hard-codes the lane root, not a tmp path, and matches the frozen claim's counter command.
