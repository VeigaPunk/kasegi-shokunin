## 2. Findings — D3 is fail-closed against missing tokens but NOT against token-presence forgery

All findings reproduced live on mutant exports of the committed tree; only `corpus/lessons/round-43.md` was mutated.

### F1 (high) — D3 accepts a correction that asserts the numeral stays 29

`limb_d3` is a pure token-presence conjunction; it never checks that the correction actually supersedes or that `26 characters` is asserted rather than incidental. This paragraph replaced the committed correction and graded **fixed**:

> Correction (round 43; appended round 44): reviewing the numeral — the fix pointer `c6ae07c6a541e0e96d0040afb6` remains 29 characters. For reference, `printf %s c6ae07c6a541e0e96d0040afb6 | wc -c` → `26`, and `c6ae07c6a541e0e96d0040afb62b45dd37711300` is a 40 character hash; 26 characters is incidental.

```
R44-D3 status=fixed detail=appended correction states 26 characters with the counting command; history kept
routed-defects total=8 fixed=8 unresolved=0 exit=0
```

The emitted detail `appended correction states 26 characters` is false in that tree — the paragraph asserts the numeral is still 29. Same result with `… is NOT superseded — … still measures 29 characters` (mutant M4). A second appended paragraph re-asserting 29 after the real correction also leaves D3 fixed (mutant N2): the counter grades the *first matching* paragraph, not the *effective* correction.

### F2 (high) — append-only enforcement is a bare substring test; deleting the erroneous history still passes

`limb_d3` checks `if "29-character prefix" not in lesson` and calls this "the original 29-character sentences are gone (append-only violated)". But the committed correction paragraph itself contains the quoted literal `"29-character prefix"` (round-43.md, correction block first line). Mutant M7 deleted **both** original erroneous sentences (the `the fix pointer, a 29-character prefix` quote block at L90 and `The fix pointer is a 29-character prefix` at L101 — verified absent in the mutant, present in the committed tree) while keeping the correction paragraph:

```
R44-D3 status=fixed detail=…; history kept
```

`history kept` is emitted while the history is gone — the phrase survives only inside the correction itself (1 occurrence vs 3 in the committed tree). Mutant Q3 confirms the symmetric in-place rewrite: both sentences rewritten in place to `26-character prefix`, correction kept (which still quotes `29-character prefix`) → `fixed`. Either way the in-place-rewrite prohibition the docstring claims (`Append-only is enforced where the protocol demands it: a correction must sit AFTER the text it corrects`) is not enforced for D3 — the only surviving "evidence" of the wrong numeral is the correction's own quotation of it. (An all-out rewrite that drops the phrase everywhere does fail: P1 → `the original 29-character sentences are gone`.)

### F3 (medium) — no positional binding for D3

Mutant M3b: committed correction paragraph moved to the **top** of `corpus/lessons/round-43.md`, *before* the two erroneous sentences it supersedes → `fixed`. `limb_d1` explicitly enforces `scorecard.find(corr) <= idx` (correction after the round-43 row); `limb_d3` has no equivalent position check, so an insert-before-corrected-text "correction" — the opposite of the protocol's append-only ordering — is invisible to the counter.

### F4 (medium) — the counting command is a string, not a measurement

The counter never executes the command; it requires the literal `printf %s c6ae07c6a541e0e96d0040afb6 | wc -c` to appear. Mutant M5 (committed correction with `→ `26`` flipped to `→ `29``) → `fixed`. The check `if len(FIX_POINTER) != 26` is a tautology on a hardcoded constant — it cannot fail and is dead code, not a re-derivation.

### F5 (low) — corrected pointer not bound to the pointer asserted at the erroneous lines

Mutant Q1: the pointer at the erroneous line 90 swapped to a different 26-char string `aaaa…` while the correction still names `c6ae07c6a541e0e96d0040afb6` → `fixed`. The limb verifies the correction paragraph, not that it corrects *the* pointer the lesson mis-counted.

## 3. Verdict on the assigned item

- The assigned weak-correction attack **fails to falsify** D3: `unresolved`, exit 1, and a second (weaker) appended correction also stays `unresolved`. D3's token conjunction is conjunctive-in-one-paragraph and is not defeatable by omission (W1–W4, M2, N3).
- D3 **is** falsifiable through token-presence forgery: F1 (assert-29 correction passes), F2 (history deletion passes because the check is satisfied by the correction's own quotation of `"29-character prefix"`), F3 (no position check, unlike D1), F4 (counting command never executed, dead `len` check), F5 (pointer unbound). The counter proves the literal bytes are present in one paragraph; it does not prove the paragraph is a superseding correction, that it sits after the corrected text, or that the wrong sentences survive as history.
