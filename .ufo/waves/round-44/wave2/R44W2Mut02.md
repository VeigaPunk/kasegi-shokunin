**Two coverage findings against the D3 predicate** (reported, not acted on):

1. **The counting command is never executed.** `limb_d3` matches `COUNT_COMMAND` as text (`r44-routed-defects.py:169,258`) but never runs it or compares its output to the stated numeral. A correction whose counting command is present but whose stated result is wrong grades D3 **fixed** (mutE). Since §6.3 was routed precisely because "a numeric claim needs its counting command", the printed value is the substance of the repair and is currently ungraded.
2. **"Appended" is asserted, not checked.** `limb_d3` verifies the old sentences survive (`:251-252`) but never verifies the correction sits after them, so a correction *prepended* to the file grades fixed (mutF). Its sibling `limb_d1` does enforce this (`:206-207`), so the asymmetry is internal to the instrument.

Neither finding falsifies C1: the committed correction at `corpus/lessons/round-43.md:167-175` is genuine, append-only, and its stated output (`26`) is the true length of the pointer.

## 8. Limitations

- I graded the D3 limb only. D1, D2 and D4–D8 were observed as `fixed` in every run only to confirm that each mutant's failure was attributable to D3 (fixed=7, unresolved=1); I did not attempt to kill those limbs.
- The mutants were applied to a `git archive` export of `8063547d`, not to a git checkout. The export is byte-faithful for every file the counter reads (verified by the identical `sha256` of the restored lesson and by the instrument hash check), but the export has no `.git` directory, so any counter behaviour that depended on git metadata would not have been exercised. `limb_d3` reads only the working tree (`Tree.read`), so this does not affect the result.
- `mutE`/`mutF`/`mutG` are my own constructions. They are plausible single-defect degradations, not mutations of any shipped artifact; they demonstrate what the predicate does not check, not that any existing file is wrong.
- I did not examine whether the same command-text-only weakness exists in the C2 counter or the wave-registry emitter — out of this seat's scope.
- I did not run the counter against the frozen base `5ab3a60` export myself; I relied on the lane's committed control `.ufo/waves/round-44/controls/c1-counter-baseline.txt` for that figure (it shows `R44-D3 status=unresolved`, `fixed=0 unresolved=8`).
