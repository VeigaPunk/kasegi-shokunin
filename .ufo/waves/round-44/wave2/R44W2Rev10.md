## Findings by severity

### Medium — count can pass without F26 or a row in the Frontier table

`ROW_RX` only checks a line prefix anywhere in `corpus/README.md` (`r44-frontier-count.py:41,50-59`); it does not track Markdown table boundaries/fences, validate unique IDs, or require F26. `--expect` checks only the admitted count (`:78-84`). The committed README has non-frontier tables and a fenced receipt block (`corpus/README.md:426-455`), but the scanner has no context for either.

Reproduction on scratch copies of the base export:

- `python3 corpus/instruments/r44-frontier-count.py --root /fast/scratch/hyaku/kasegi-r44/R44W2Rev10/fx2/base_plus_dup_F25_row --ids --expect 26` → `frontier rows=26 admitted=26`, exit 0; IDs end `...,F25,F25` (26 rows but only 25 distinct IDs; F26 absent).
- `python3 corpus/instruments/r44-frontier-count.py --root /fast/scratch/hyaku/kasegi-r44/R44W2Rev10/fx4/F27_no_F26 --expect 26` → `frontier rows=26 admitted=26`, exit 0; the added row is F27, not F26.
- A synthetic F26 row inside a fenced block or an unrelated receipt table likewise makes the base export report `frontier rows=26 admitted=26`, exit 0.

These are not present in the committed tree, whose 26 actual rows are F01–F26. They show the counter alone does not establish the C2 kill-rule requirement that F26 land; the claim also requires its source, knowledge entry, registry row, and non-author agreement (`claims.json:22`). Do not treat this as evidence that the current tree lacks F26.

### Low — escaped pipes before the status cell shift the parsed column

`r44-frontier-count.py:54` uses `split("|")`, which does not honor Markdown's escaped `\\|`. The README already uses escaped pipes in table cells at `corpus/README.md:444-446`. On a base-export fixture with an admitted F26-shaped row whose topic contained `\\|`, the counter printed `frontier rows=26 admitted=25` and `--expect 26` exited 1: the escaped pipe creates an extra cell, so `cells[2]` is no longer the status. This is a fail-closed undercount, not a false pass. No current F01–F26 row has an embedded pipe, so the committed count is unaffected.

### Low — accepted row syntax is narrower than the table content model

The prefix regex requires exactly `| F<digits> |` at column zero (`:41`): an indented row or `|  F26 |` is skipped. A two-cell malformed row is also skipped before incrementing `rows` (`:55-57`). These shapes undercount rather than pass; none occurs among the committed F01–F26 rows.
